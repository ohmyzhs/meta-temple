# 청연산사 출시판 업그레이드 설계 (2026-11-05, 2차 수정)

프로토타입(temple.lotiony.com, 커밋 799180c)을 실제 출시 제품 수준으로 끌어올리는 설계.
요구사항은 사용자의 11개 항목 + 1차 검토 뒤 받은 6개 수정 지시. "사용자 결정"과 "내 판단(설계자 판단)"을 구분해 적는다.

## 1. 의도

- 링크 하나로 들어오는 **무설치 웹 산사**라는 성격은 유지한다 (Three.js, 빌드 없는 ES 모듈, 오라클 VM + Cloudflare).
- 지금 그래픽은 "손으로 깎은 폴리곤 + 캔버스 텍스처"라 실제 공간감에 한계가 있다. 사용자는 **실사 같은 질감·공간감**을 원하고 "수십만 폴리곤을 깎는 방식"은 지양하라고 했다.
- **기본 분위기는 밝고 쾌청한 날씨**다. 흐림·비·눈은 고를 수 있는 선택지일 뿐이다. 시간은 실시간(한국 시각)을 따르되, **밤에도 달빛 아래 윤곽이 보이고 하늘에는 은하수가 보인다** (사용자 지시).
- 지금은 과금하지 않지만, 수만 명 규모의 서버비를 감당하려면 **나중에 과금이 들어간다** (토스페이먼츠). 구조는 지금부터 대비한다.

### 성공의 모습
- 처음 들어온 사람이 "사진 같다, 날이 참 맑다"고 느끼는 숲길·마당·법당. 법당 안은 실내라는 것이 분명하고, 불상은 위엄이 있다.
- 일반 스마트폰(세로 360~430px)에서 모든 버튼을 한 손으로 쉽게 누르고, 아이콘만 보고 무엇인지 안다.
- 다른 사람이 쓴 글에 욕설·성적인 말이 보이지 않는다.
- 다실에서 스님과 실제로 이야기를 주고받는 느낌이 든다.

### 하지 않을 것 (non-goals)
- 네이티브 앱, 설치형 클라이언트.
- 이번 단계의 실제 결제, 카카오 로그인 자체 구현 (구조만 준비).

### 실패로 볼 것 (anti-goals)
- 실사화하느라 첫 입장이 수십 초 걸리거나 폰에서 멈추는 것.
- 화면이 칙칙하거나 흐릿한 것 (기본은 쨍하게 맑은 날), 밤에 아무것도 안 보이는 것.
- 기능은 되지만 화면이 버튼·출처 표기로 뒤덮이는 것.
- 생성형 이미지가 서로 그림체가 달라 누더기처럼 보이는 것.

## 2. 이미 한 것

- 실서버 돌탑에서 성적인 글 5건(같은 작성자 「비 개인 뒤의 조약돌」: 쉐엑스·Cex·세엑스·Sex·쉐엑스)을 `hidden=true` 로 숨김. 지금 공개 목록 3건. 되돌릴 수 있게 숨김으로 처리.

## 3. 제작 방식 (요구 1·4·5의 핵심) — 사용자 승인됨

### 결론: Three.js 유지 + Blender 파이프라인 + 실측 스캔·사진 질감·생성형 이미지. Unity 미사용

실사감을 만드는 것은 엔진이 아니라 네 가지다.
1. **실제를 잰 형태와 사진 질감**: 레이저 스캔·사진측량 모델, 사진으로 만든 PBR 텍스처(색·노멀·거칠기·AO).
2. **구워 둔 빛(라이트맵)**: 실내의 은은한 반사광·기둥 밑 그늘. Blender Cycles 로 미리 굽는다.
3. **적은 폴리곤 + 고해상도 노멀맵**: 스캔의 수백만 폴리곤을 수만 개로 줄이고 잃은 디테일은 노멀맵으로 굽는다.
4. **실제 하늘 빛(HDRI)**: 맑은 날 하늘을 찍은 HDRI 로 하늘·반사·주변광을 만든다. 쨍한 낮 분위기의 핵심.

Unity Web 은 빌드가 수십 MB 이상이라 첫 입장이 느리고 모바일 브라우저 메모리 한계에 자주 걸린다. 위 네 가지는 Three.js + glTF 로 구현된다.

### 에셋 출처
| 출처 | 라이선스 | 쓸 곳 |
|---|---|---|
| **생성형 이미지** (gpt-image, ego-browser 에 로그인된 Google Flow) | 생성물 | 단청·꽃살문·한지·흙벽·돌담 등 이음새 없는 질감, 원경 산·운무 그림, 법당 옆벽 벽화, UI 아이콘·버튼 그림, 공덕 도감 아이템 그림, 차담 스님 초상, 입장·로딩 그림 |
| 국가유산청 3D 스캔 (공공데이터포털·국가유산 디지털서비스) | 공공누리 1유형 | 불상 삼존, 삼층석탑, 석등, 당간지주 |
| Poly Haven, ambientCG | CC0 | 흙·자갈·화강암·이끼·풀·나무껍질·목재 PBR, **맑은 하늘 HDRI** |
| 문화포털 전통문양, 국가유산·박물관 공개 이미지 | 공공누리 | 단청 원본 문양, 후불탱화(실제 불화) |

- 사용자 지시: 공공 자료만으로는 부족하므로 **생성형 이미지를 적극 활용**한다.
- 내 판단: 불상(형태)과 후불탱화(도상)만은 실제 자료를 우선한다. 생성형은 부처님 얼굴·수인·도상을 틀리게 그리기 쉬워서다. 사용자가 원하면 바꾼다.
- 그림체 일관성(내 판단): 생성 전에 **화면 그림체 기준표(아트 바이블)** 한 장을 먼저 만들어 색감·빛·질감 방향을 고정하고, 모든 생성 프롬프트가 그것을 따른다. 생성물은 매번 무엇을 만들었는지 사용자에게 보여 준다.

「국가유산 3D 원형 정보자원 목록」(공공데이터포털 15147467, 1,838건)에서 확인한 실측 데이터 (zip(obj), 원본 기준):
- 대웅전 삼존: 진주 청곡사 목조석가여래삼존좌상(389만 폴리곤, 208MB), 창녕 관룡사 목조석가여래삼불좌상 및 대좌(269만, 151MB), 진주 응석사 목조석가여래삼불좌상(82만, 150MB)
- 삼층석탑: 경주 고선사지·황복사지, 예천 동본리, 군위 지보사, 함양 벽송사 등
- 그 밖: 경주 보문사지 연화문 당간지주, 창녕 관룡사 대웅전 관음보살 벽화
- 실제 파일을 받는 경로(신청 필요 여부)는 스파이크에서 확인한다.

### 파이프라인
1. `tools/blender/*.py` — Blender 를 화면 없이 돌리는 파이썬 스크립트로 장면을 만든다 (다시 만들 수 있고 git 으로 관리).
   - 법당: 기둥·창방·공포·우물천장·닫집·수미단·꽃살문을 실제 비례로 모델링, UV, 사진·생성 텍스처, Cycles 라이트맵.
   - 스캔: 줄이기 → 노멀·AO·색 굽기.
2. 최적화: `gltf-transform`(npm 개발 도구)으로 Meshopt + KTX2 + LOD. 폰 1K, 데스크톱 2K 텍스처.
3. 런타임: `GLTFLoader` + `KTX2Loader` + `MeshoptDecoder`(three/addons, jsdelivr 고정 버전). 구역별 GLB, 지금 구역 + 다음 구역만 받는다.
4. 용량: 첫 입장(숲길) 폰 15MB 이하, 구역당 5~20MB 를 뒤에서 미리 받기 (사용자 승인).

### 분위기: 맑은 날이 기본, 밤에도 윤곽이 보이게 (사용자 지시)
- 시간 기본값은 지금처럼 **실시간(한국 시각)** 을 유지한다. 날씨 기본은 **맑음**, 흐림·비·눈은 고를 때만.
- 맑은 낮: CC0 맑은 하늘 HDRI(하늘·반사·주변광), 선명한 그림자, 옅은 안개(먼 산만 살짝), 채도·대비를 살린 색 보정. 지금보다 노출·하늘 파랑·햇빛 세기를 올리고 회색 안개를 줄인다.
- **밤: 밝은 달빛 아래 산사.** 완전히 깜깜한 화면은 금지.
  - 하늘: 은하수 띠가 또렷하고 별이 아주 많은 밤하늘 (별 수천 개 + 은하수 띠 텍스처 — CC0 밤하늘 HDRI 또는 생성형 은하수 하늘, 지평선 쪽은 옅은 남빛). 밝은 달과 달무리.
  - 빛: 은백색 달빛을 주광으로(그림자 있음), 하늘빛 보조광을 올려 지붕선·담·나무·석탑의 **실루엣과 윤곽이 늘 보이게**. 화면 밝기에 최저선을 두어(노출 하한) 아무리 늦은 밤도 형태가 사라지지 않게 한다. 연등·석등·창호 불빛은 따뜻한 점으로.
  - 확인 기준(내 판단): 자정 화면 스크린샷에서 대웅전 지붕선, 앞마당 석탑, 숲길 나무 줄기가 맨눈으로 구분될 것.
- 구운 빛(내 판단): 실외는 해와 상관없는 그늘(AO)만 굽고 해·달·날씨는 실시간. 법당·다실 실내는 「낮」「밤(촛불 + 달빛이 문으로)」 두 벌 라이트맵을 모두 만든다 — 실시간이 기본이라 밤 접속도 흔하다. 지금 시간대에 맞는 벌만 먼저 받고, 다른 벌은 뒤에서 받는다.

### 스파이크 통과 기준 (내 판단)
- 화면: 지금 화면과 나란히 놓고 질감·빛·맑은 하늘이 실사에 확실히 가까울 것 (사용자가 스크린샷으로 판단).
- 성능: 중급 안드로이드(갤럭시 A5x급)·아이폰 12급에서 30fps 이상, 구역 내려받기 폰 5MB 이하.
- 라이선스: 공공누리 1유형은 출처표시만 하면 변경·상업적 이용 허용. 다른 유형은 쓰지 않는다.
- 스캔을 못 받으면: 절차적 모델 + 사진·생성 텍스처 + 구운 빛으로 가고, 결과를 보여 준 뒤 정한다.
- 스파이크 내용: 실측 석탑 1 + 법당 실내 한 칸 + 맑은 낮 HDRI 하늘 + 생성형 질감 2~3종(단청 띠, 흙벽 등).

### 배포 방식 (사용자 결정: 묶음마다 확인 후 배포)
- main 에 푸시하면 곧바로 실서버에 배포되므로, 묶음은 각자 브랜치(worktree) → 통합 브랜치 `launch` → 화면 확인 → 사용자 확인 후 main.
- 서버 프로토콜(돌탑 위치, 이름·장비 동기화)은 캐시된 옛 화면과 섞여도 깨지지 않게 새 필드를 선택 항목으로 더한다.

## 4. 요구사항별 설계

### 요구 1·4. 대웅전 확장·실내외 구분, 모든 배경 실사화
- 대웅전 규모를 정면 5칸 × 측면 3칸으로 키운다 (지금 16m × 10m → 약 22m × 13m, 내부 천장 높임). 조선 후기 다포계 팔작 대웅전 일반형 (사용자 결정).
- 실내외 구분: 정면 꽃살문 분합문, 두꺼운 벽, 실내 전용 빛, 문턱을 넘을 때 짧은 디졸브와 실내 카메라 규칙(요구 2).
- 불상: 실측 스캔 삼존(1순위 진주 청곡사 목조석가여래삼존좌상)을 수만 폴리곤으로 줄이고 노멀·색·AO 를 구워 개금 재질로. 못 받으면 현재 조각을 노멀맵 원본으로만 쓰고 저폴리 + 텍스처로.
- 담·돌·흙·풀·석탑: 기와 얹은 돌담·토담, 흙길·자갈, 사진 알파 풀, 스캔 석탑·석등.

### 요구 5. 산사를 한 바퀴 두르는 숲길 (사용자 수정 반영)
- 지금의 짧은 직선 숲길을 **산사 전체를 둘러싸는 순환 산책로**로 넓히고 잇는다: 일주문 숲길 → 계곡 따라 → 뒷산 능선(산사를 내려다보는 전망) → 대숲 → 후원 다실 뒤 → 다시 숲길. 갈림길로 마당·다실에도 들어갈 수 있다.
- 길 중간의 쉼: 돌 쉼터, 나무 그루터기, 돗자리 펴는 자리, 전망 바위, 작은 다리, 약수터. 모두 좌복처럼 "고른 자리로 걸어가 앉기".
- 걸을 수 있는 영역은 산책로 스플라인 + 쉼터 영역으로 정의 (지금 `isWalkable` 확장). 구역 GLB 를 산책로 구간별로 나눠 받는다.

### 요구 8. 돌탑 어디서나
- 산문 밖(순환 산책로 포함) 모든 걸을 수 있는 땅에서 「돌 올리기」: 1.5m 안에 돌탑이 있으면 한 층 더, 없으면 새 돌탑 1층.
- 서버 `stones` 에 `cairn_id, x, z` 를 더해 공유. 가까운 돌탑 위주로 일부만 그린다. 한 구역 개수 상한.

### 요구 2. 장소 전환과 카메라 가림
- 가람 이동·산문·법당 출입은 디졸브 전환(예불 듣기의 가림막 재사용) + 도착지별 미리 정한 구도.
- 3인칭 가림: 카메라와 캐릭터 사이를 실제 지오메트리(담·처마·지붕·벽)로 광선 검사 → 막히면 카메라를 당기고, 가리는 물체는 반투명 디더링.
- 법당 안·다실 가는 통로: 낮고 가까운 전용 카메라 규칙.

### 요구 3·11. 모바일 UI, 아이콘 에셋, 뒤로가기
- 아이콘: 행동(합장·큰절·가부좌·헌향·탑돌이·다선)·도구(시간·날씨, 소리, 내 모습, 수행 기록, 도움말)·장소 4곳을 **그림 아이콘**으로 새로 (아트 바이블에 맞춰 생성형으로 원안 → SVG 로 정리). 장소는 숫자 대신 건물 그림 + 이름.
- 오작동 방지: 모든 조작 요소를 `<button>` + 아이콘 + `aria-label`, `user-select: none`, `-webkit-touch-callout: none`, `-webkit-tap-highlight-color: transparent`, `touch-action: manipulation`. 버튼 전체가 터치 영역, 최소 48×48px.
- 배치: 하단 독(자주 쓰는 행동 4 + 「더보기」 접이식), 우측 상단 도구는 메뉴 하나로 묶기(펼치면 아이콘 + 글자), 장소 이동은 그림·이름 목록 시트. 기본은 접힘.
- 뒤로가기(안드로이드): 입장 시 History API 로 한 단계 쌓고 `popstate` 에서 열린 창·시트·예불 듣기·차담을 먼저 닫는다. 닫을 것이 없으면 "한 번 더 누르면 산문을 나섭니다" 안내 후 2초 안에 다시 눌러야 나간다.

### 출처 모아보기 (사용자 수정 반영)
- 일반 화면에서 출처 표기를 모두 걷어낸다 (예불 목록 아래 안내, 도움말의 「소리의 출처」 등).
- 도움말 맨 아래와 메뉴에 작은 「자료 출처」 링크 하나 → 따로 여는 **출처 모아보기** 화면: 소리·3D 스캔·사진 질감·문양·HDRI·생성형 도구를 분류별로. 공공누리 1유형의 출처표시 의무는 이 화면으로 지킨다.

### 요구 10. 심검당 차담 재설계 (사용자 수정 반영)
채팅창이 아니라 **스님과 마주 앉아 말을 주고받는 장면**으로.
- 화면: 다실로 들어가면 예불 듣기처럼 HUD 를 거두고, 찻상 너머 스님이 보이는 구도로 카메라를 고정. 아래쪽 3분의 1 에 대사 상자(스님 초상 + 이름 + 말풍선), 글자가 한 자씩 나타나고 누르면 바로 다 보인다.
- 스님 목소리(TTS):
  - 1단계(지금, 무료): 브라우저 내장 음성 합성(Web Speech API, 한국어 남성 음성, 느린 속도). 켜고 끌 수 있음. 기기마다 음색이 다르다.
  - 고정 대사(첫인사·차 따르기·작별 등): Typecast 로 미리 녹음한 파일을 자산으로 (사용자가 Typecast 를 갖고 있음). 품질이 가장 좋다.
  - 2단계(과금 이후): AI 답변도 서버 음성 합성(클라우드 TTS)으로, 같은 문장은 캐시.
- 내 응답: 매 차례 **예상 응답 3개** 단추 + 「직접 말하기」(누르면 입력칸이 키패드 바로 위에 붙음, `visualViewport` 로 높이 따라가기). 데스크톱은 숫자 키 1·2·3 으로도 고르기.
- 스님 두뇌: **AI 대화(Claude API)**. 서버 `temple-live` 에 `/api/monk` 를 두고 API 키는 서버에만. 화면에 지금 있는 `monkChatEndpoint` 자리에 연결.
  - 페르소나: 청연산사 다실의 노스님. 존댓말, 짧고 따뜻하게(2~4문장), 설교하지 않고 들어 주기, 차·계절·산사 풍경으로 말을 잇기, 필요할 때 짧은 게송이나 경구 한 줄. 정치·종교 논쟁·의료·법률 단정 회피, 다른 종교 비하 금지, 실제 사람인 척하지 않음.
  - 응답 형식: 구조화 출력(JSON) `{ reply, suggestions: [3개], verse? }` 로 예상 응답까지 한 번에.
  - 안전: 입력은 욕설 필터(요구 9 공용 모듈) 통과 후 전송. 자해·자살 신호가 보이면 스님 말투를 유지하되 반드시 **자살예방상담전화 109**(2024년 1월부터 통합 번호, 24시간) 안내를 함께. 출력도 필터 한 번 더.
  - 비용 통제: 사람(profileId)·IP 별 하루 무료 차례 수(예: 20번), 대화 기록은 최근 몇 차례만 보냄, 페르소나 프롬프트는 캐시, 답 길이 상한. 한도가 끝나면 "찻물이 식었습니다, 내일 또 오세요" + 미리 쓴 대화 나무로 이어가기. 나중에 과금되면 찻잎(추가 대화) 상품과 연결.
  - 화면에 "차담 스님은 AI 입니다" 를 작게 밝힌다 (내 판단).
  - AI 서버가 없거나 끊기면 지금의 규칙 기반 답(`generateMonkResponse`)과 대화 나무로.
- 모델 선택은 비용 결정이라 사용자에게 묻는다 (6장).

### 요구 7. 이름 직접 짓기, 계정 이전 구조
- 이름: 입장 화면·내 모습 메뉴에서 직접 입력(2~12자, 욕설 필터). 무작위 법명 추천도 유지.
- 로컬 저장: `{ schemaVersion, profileId(uuid), updatedAt, profile, stats, items, wishes, ... }` 한 덩어리 + 버전별 마이그레이션 함수 체인 + 내보내기/가져오기(JSON 백업).
- 나중의 카카오 로그인: 서버 `accounts(kakao_id ↔ profileId)`, 첫 로그인 때 로컬 상태 업로드·병합(횟수는 큰 값, 아이템은 합집합). 결제(아래)도 이 계정에 묶인다. 이번에는 구조와 `/api/profile` 자리만.

### 요구 9. 욕설·음담패설 가드레일
- 서버(최종 판정)와 화면(즉시 안내)이 같은 규칙 모듈.
- 정규화: NFKC → 소문자 → 공백·기호·이모지·제로폭 문자 제거 → 한글 자모 분해 → leet(0→o, 3→e, $→s 등)·한영 음차(섹스·쎅스·섹쓰·쉐엑스·세엑스·sex·cex 류)를 같은 꼴로 모아 비교.
- 사전: 한국어 욕설·성적 표현(공개 목록을 라이선스 확인 후 기반 + 보강), 영어, 연락처·링크·광고 패턴.
- 적용: 연등·기와·돌탑 글, 이름, 차담 입력·출력.
- 운영: 신고 버튼(서로 다른 3명 신고 시 자동 숨김), 작성자별 연속 등록 제한, `deploy/mod.sh` 관리 스크립트(숨김·되살림·검색).

## 5. 과금 대비 (사용자 지시: 지금은 안 하지만 나중에 한다)

### 참고: 「산사(SANSA, sansatemple.com)」
- 2026년 10월 말 공개, 사흘 만에 60만~90만 명 방문으로 보도. 1인 개발자가 AI 코딩으로 제작.
- 과금은 **자율 후원뿐**: 첫 화면의 「공양미 보내기」 두 개 — 카카오페이 송금 QR(`qr.kakaopay.com`)과 Buy Me a Coffee. 유료 아이템·입장료 없음. 서버비 부담 때문에 이용자 요청으로 넣었고, 접속 폭주로 한때 멈췄다.

### 우리 방식 (나중에 토스페이먼츠, 사용자가 사주언박싱에서 이미 붙여 봄)
후보 상품 (실제 사찰의 공양·불사와 같은 결):
1. **공양 올리기(자율 후원)**: 금액 고르기(3천·1만·3만·직접). 감사 연출 + 「공양 연등」(이름표가 달린 금빛 연등, 일정 기간 마당에 걸림) + 원하면 공양자 명단.
2. **디지털 불사**: 인등(1개월 밝히는 등), 금빛 기와, 금빛 돌탑 돌 — 꾸밈과 표시 기간만 다르고 수행 보상과는 별개.
3. **찻잎(추가 차담)**: AI 차담 무료 한도를 넘는 대화.
4. **도반 정기 후원**: 월 정기결제(토스 빌링) — 나중.

원칙 (내 판단):
- 공덕 도감·칭호 같은 **수행 보상은 돈으로 사지 못한다**. 돈은 꾸밈·표시·추가 대화에만.
- 실제 사찰 기부가 아니므로 "서비스 운영 후원"으로 표기하고, 기부금 영수증이 되지 않음을 분명히 한다. 사업자 정보·환불 규정 표시(전자상거래법), 토스 가맹 심사 요건 확인.

지금 해 둘 구조 (결제 코드는 만들지 않음):
- 계정 구조(요구 7)에 서버 쪽 **보유 권리(entitlements)** 테이블 자리: `entitlements(profile_or_account, sku, source: 'merit'|'purchase', granted_at, expires_at)`.
- 상품 목록은 설정 파일(`sku, 이름, 가격, 기간, 효과`)로, 화면은 기능 플래그로 숨김.
- 결제 공급자 어댑터 자리(`server/payments/toss.js` 인터페이스만): 주문 생성 → 결제창 → 서버 승인(confirm) → 권리 지급, 웹훅으로 상태 동기화.
- 공양 연등·금빛 기와 같은 유료 꾸밈이 실시간 동석·공유 서원에 실릴 필드(선택 항목) 자리.
